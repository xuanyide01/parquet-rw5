# 《PARQUET》资源提取与转换记录

## 已确认资源

比较 Steam 目录及补充目录后，`bgimage/fgimage/scn/evimage.xp3` 的 SHA-256 完全相同；启动和 UI 数据存在版本差异，具体见 `reports/source-comparison.json`。转换以这组共同剧情/美术资源为基础，启动数据采用能够完成无界面批处理的补充副本。原游戏目录只读，另建研究工作副本。

此次成功方法不依赖桌面操作：使用原引擎 `-startup=<自编 TJS>`，加载其随附的 PackinOne 插件，调用 `Storages.exportFile` 将所需资源写出，结束后自动退出。自编脚本不创建窗口、不执行原游戏主流程。XP3 内路径使用绝对 `file://./...>entry`，避免 `data.xp3` 项目目录导致相对定位错误。

提取了 1,609 个资源，合计 884,885,400 字节。每个文件独立对照 XP3 索引的解压长度和 Adler-32，并生成 SHA-256；见 `reports/engine-export.json`。研究中尝试过的已知 XP3 过滤器均未通过校验，未将其解码结果用于正式转换。

## 脚本与静态层

1. 解开原作 FE FE 01 FF FE 文本包装，恢复 UTF-16 码元。
2. 使用 FreeMote 解码 17 个 SCN 和事件/UI PIMG；严格解析 12 个 PBD，并验证解压与结构消耗。
3. SCN 文本记录为 5 元素结构，四语言数组的索引 2 是简体中文，最后一项是画面快照。原作场景中包含虚拟跳转节点，不能把所有数字行号当作文本索引。
4. `.stand`、`.sinfo` 和 PBD 决定身体、服装、姿势与表情。按原图层位置、顺序、透明度及混合模式合成。解析出 1,013 个立绘请求和 496 个原始 TLG 层；两个桥姬差分通过唯一、精确的叶名后缀补全原配置缺少的父路径。
5. 身体图复用并烘焙完整基础表情；原作表情先按原图层合成，再填入与身体相同尺寸的透明画布。脸部比较更多 RGBA 颜色、可见像素调色板和旧版编码，以原图误差选择；透明边缘出现残影时回退到六位 RGB 完整合成图。背景/CG 保留画幅缩至 320×216 边界，JPEG 质量 62；立绘为 262 像素高的透明 PNG，适当裁取上半身；身体与完整画布表情层复用，脸部独立分配调色板。1,013 个立绘请求均来自 3750×5313 原画布，使用相同的约 0.15 原图像素比例；按姿势的脸部锚点定位，底部统一落在屏幕 y=286。单人、多人和 Another View 不因衣服包围框宽度而改变人物比例。不同场景仍使用对应原作背景，不用单一占位图替代。
6. CG 鉴赏使用真实 `cglist.csv` 与 `imagediffmap.csv`。部分遗留模板包含其他作品的旧人物名，未使用其生成路线或 CG 名称。
7. 原作文本含一个 U+FFFC 对象替换标记，转换源文本保留，阅读界面隐藏该非显示标记；其他中文记录逐条匹配。字体为随游戏提供的思源黑体简中 Regular 子集，覆盖全部实际台词和人物名，重命名为 ParquetWatchText。

## 控制流

`data/scenario/start.ks` 定义 SIDE STORY 从文件 00 开始、正篇从文件 01 开始、AFTER STORY 从文件 15 开始。对照原作标题解锁顺序，首次 START 先进入前传，前传结束返回标题；再次 START 阅读正篇，完成正篇后显示 AFTER STORY。

两处后日谈选择节点均保留“叫醒茨木”“叫醒城门”及其原始场景目标。其中主节点还保留 `SetBranchFlags` 的声明式状态值。不执行任意原作表达式、不补造选择或线路。按场景图保留 101 条直接边与两处分支。`reports/source-equivalence.json` 独立比较原始 SCN 与输出运行指令。

阅读标题和存档摘要直接使用每条原作文本快照中的 `showdate.date`；由原作章节命令和流程图标题映射为 `pre story`、`prologue`、`CHAPTER 1-1` 等名称，避免将文件编号当成章节序号。

每 32 条运行指令分块，避免一次读入全剧本；保留最多 8 个回看检查点。章节快进按原作 `scnchart` 标签寻找边界，跨块处理时仍检查选项；遇到选项原地停止，等待玩家选择。存档包含真实场景号、块内位置、角色、背景、选项与分支变量。

## 复现目录

交付的 `src` 可直接编译。重新提取还需要自行准备合法原作及以下研究目录（原始大图和 Windows 程序不随交付包分发）：

```
work/
  parquet-rw5/                  # 本项目
  parquet-probe/
    game/                      # 自备引擎、插件和 XP3 的工作副本
    batch/
    extracted-engine/          # extract-engine.py 输出
    scenarios/                 # FreeMote 解码 SCN JSON
    evimage-json/              # FreeMote 解码 PIMG 及图层
    decoded-layers/            # GARbro 解码所需 TLG
```

转换脚本：`extract-engine.py` → `decode-resources.py`（文本包装 / FreeMote / PBD） → `convert-story.py` → `plan-portraits.py` → `decode-layers.ps1` → `prepare-images.py` → `improve-portraits.py --apply` → `compress-static-v015.py` → `generate-layout.py` → `optimize-pngs.py` → `generate-layout.py` → `prepare-ui.py` → `prepare-cutins.py` → `build-font.py`。当前解码路径可在脚本头部按本地工具位置调整；普通构建不需要这些外部大资源。

提取调用参考 [KiriKiri 命令行文档](https://wamsoft.github.io/krkrz_dev/en/guide/CommandLine/) 与 [Storages 文档](https://wamsoft.github.io/krkrz_dev/en/reference/Storages/)。图像和脚本工具的第三方许可证应分别遵守；相关二进制并未打入本应用。
